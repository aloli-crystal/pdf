All notable changes to pdf are documented here. The format
follows https://keepachangelog.com/1.1.0/[Keep a Changelog] and
versioning follows https://semver.org/[SemVer].

== v1.21.0 — 2026-09-24

=== Added

* **SVG rendering: `text-anchor`** (`start`, `middle`, `end`) on `<text>`, measured with the font in use.
* **SVG rendering: opacity** — `opacity`, `fill-opacity` and `stroke-opacity` (number or percentage) become an ExtGState; `opacity` multiplies the other two.
* **SVG rendering: `font-weight`** — `bold`, `bolder` or ≥ 600 use the bold font.
* **`Page#svg(…, font:, bold_font:)`** — optional TrueType fonts for `<text>`; without them WinAnsi Helvetica turns ≈, →, ■… into `?`.

=== Fixed

* **SVG rendering: inherited properties** — `font-size`, `font-weight` and `text-anchor` set on the root `<svg>` or a `<g>` now apply to `<text>` (the size fell back to 12).
* **SVG rendering: white space** — runs of white space in a `<text>` collapse to one space, as in SVG.
* **`Page#svg` no longer changes the caller's current font**: it is restored after drawing.

== v1.20.3 — 2026-08-05

=== Fixed

* `PDF::Table#row_colors` était accepté et stocké mais jamais
  appliqué au rendu : aucune cellule ne recevait la couleur de
  fond alternée. Les couleurs sont maintenant appliquées par
  ligne de données (le header en est exclu), sans écraser un
  `background_color` déjà fixé explicitement par cellule ou via
  `cell_style`.
* `PDF::Page#table` appelait `Table#draw`, qui ne pagine jamais :
  un tableau plus haut que la page courante continuait de se
  dessiner hors-page. Route maintenant l'appel via
  `Table#draw_with_page_breaks`, qui crée les pages
  supplémentaires nécessaires et répète les lignes d'en-tête.
* Les `transform` SVG posés directement sur une forme (`<rect>`,
  `<circle>`, etc.) étaient silencieusement ignorés : seuls les
  groupes `<g>` en tenaient compte. Le transform est maintenant
  appliqué autour de chaque branche de rendu.

== v1.20.2 — 2026-06-16

=== Added

* `PDF::ReaderPage#rotate : Int32` reads the page's `/Rotate`
  attribute (ISO 32000-1 § 14.8), inheriting through the
  `/Pages` tree. Returns 0/90/180/270 (normalized to `[0, 360[`).
  Lets callers detect PDFs whose pages have been turned by a
  viewer (Preview.app, Acrobat) via the `/Rotate` tag rather
  than by rewriting the page content — important downstream
  for naive mergers that would otherwise drop the rotation
  silently. Pair with `qpdf --flatten-rotation` to bake the
  rotation before assembly.

== v1.20.0 — 2026-06-06 — Rasterizer : shading-pattern fills (scn /Pattern)

=== Added

* **Shading-pattern fills** — filling a path with a shading pattern
  (`/Pattern cs` + `scn /P`, PatternType 2) now paints the gradient
  clipped to the path's exact shape (via a coverage mask), using the
  pattern `/Matrix`. This completes the common shading workflow
  alongside the direct `sh` operator. The `cs` operator tracks the
  Pattern colour space; solid-colour operators clear any pattern.

== v1.19.0 — 2026-06-06 — Rasterizer : gradients (axial/radial shadings)

=== Added

* **Shadings** — the `sh` operator now paints gradients over the clip
  region.
  ** `Raster::Shading` — axial (type 2, linear) and radial (type 3)
     gradients, sampled per pixel via the inverse CTM, in DeviceRGB /
     Gray / CMYK / ICCBased colour spaces, honouring `/Extend`.
  ** `Raster::PdfFunction` — a PDF function evaluator (ISO 32000-1
     § 7.10) : type 2 (exponential interpolation), type 3 (stitching)
     and type 0 (1-input sampled). Drives the gradient colours.

=== Note

* Mesh shadings (types 4–7) and the PostScript-calculator function
  (type 4) are not evaluated. Shading *patterns* used as a fill colour
  (`scn /P`) are not yet wired (only the direct `sh` operator).

== v1.18.0 — 2026-06-06 — Rasterizer : dashed strokes and round joins/caps

=== Added

* **Dash patterns** — the `d` operator (dash array + phase) is honoured,
  so dashed/dotted strokes render as dashes instead of solid lines. The
  dash state runs continuously along each polyline.
* **Round joins and caps** — thick strokes now draw a disc at each
  vertex, filling the gaps that the per-segment quads left at corners
  and giving rounded line ends.

== v1.17.0 — 2026-06-06 — Rasterizer : exact (non-rectangular) clipping

=== Changed

* **Clipping is now exact** for arbitrary clip paths, not just a
  bounding-box approximation. `W` / `W*` build a per-pixel coverage
  mask (`Canvas#path_coverage`) intersected into the graphics state;
  axis-aligned rectangles keep the cheap bounding-box fast path, while
  circles, triangles, rounded rectangles, etc. are clipped to their
  true shape. `Canvas#set_clip` takes an optional coverage mask
  alongside the bounding box.

== v1.16.0 — 2026-06-06 — Rasterizer : Type1/CFF font rendering (Type 2 charstrings)

=== Added

* **CFF / Type1C glyph rendering** — the rasterizer now draws text from
  CFF font programs (`/FontFile3` : Type1C, CIDFontType0C, OpenType-CFF),
  not just TrueType.
  ** `Raster::CFFOutlines` — a Type 2 charstring interpreter (Adobe CFF
     spec § 4.3) : move/line/curve operators, `hhcurveto`/`vvcurveto`/
     `hvcurveto`/`vhcurveto`, flex operators, local/global subroutines
     (with bias), hint skipping, and width extraction. `run_charstring`
     is a parser-free entry point for testing.
  ** `Raster::Font` now dispatches between TrueType (`Raster::Glyph`)
     and CFF (`Raster::CFFOutlines`) backends, and maps code → GID for
     simple CFF fonts via the CFF custom Encoding table (formats 0/1).

=== Note

* Still not rendered : bare Type1 PostScript fonts (`/FontFile`, without
  CFF). Standard/Expert CFF encodings (non-subset simple fonts) fall
  back to identity code → GID.

== v1.15.0 — 2026-06-06 — Rasterizer : clipping (W/W*) and soft masks (/SMask)

=== Added

* **Clipping** — the `W` / `W*` operators now constrain subsequent
  painting (fills, strokes, text, images) to the clip region. The clip
  is tracked in the graphics state (saved/restored by q/Q) as the
  intersected bounding box of the clip paths (a rectangle — covers the
  common rectangular and rounded-rectangle clips; non-rectangular clips
  are approximated by their box).
* **Soft masks (`/SMask`)** — images with a soft-mask alpha channel
  (e.g. RGBA PNGs) now composite with per-pixel transparency over the
  background, via the new `Canvas#blend`. `Canvas#clip=` applies the
  clip rectangle to all painting.

== v1.14.0 — 2026-06-06 — Rasterizer : anti-aliasing (supersampling)

=== Added

* **Anti-aliasing in `PDF::Raster`** via supersampling — text, vector
  edges and images render smoothly instead of jagged.
  ** `PDF::Raster.render_page(..., supersample : Int32 = 1)` renders
     internally at `dpi × supersample`, then box-averages back to `dpi`.
     `1` = off (exact, unchanged), `2`–`4` = increasing smoothing
     (cost scales with the square).
  ** `Raster::Canvas#downsample(factor)` — integer box-average reducer.
  ** `pdftoppm` / `pdftocairo` gain `-a`/`--antialias N` (default 3).

== v1.13.0 — 2026-06-06 — Rasterizer : image rendering (XObjects, Do)

=== Added

* **Image compositing in `PDF::Raster`** — the `Do` operator now paints
  image XObjects onto the canvas, mapped through the CTM (inverse-CTM
  device sampling over the unit square).
  ** `Raster::ImagePainter` — decodes and samples : JPEG (`/DCTDecode`,
     via `stumpy_jpeg`), `/FlateDecode` samples in DeviceRGB / Gray /
     CMYK (8-bit), `/Indexed` palettes, and `/ImageMask` stencils
     (painted in the current fill colour). Unsupported filters
     (CCITT/JPX/JBIG2) and exotic depths are skipped.
  ** `Raster::Matrix#inverse` — affine inverse for the device→image map.
  ** Form XObjects (`Do` on a `/Subtype /Form`) are now recursed into
     (depth-guarded), applying the form `/Matrix` and resources — so
     images and vectors nested in forms render too.

=== Note

* Still not rendered : Type1/CFF (non-TrueType) text, soft masks
  (`/SMask` alpha), CCITT/JPX/JBIG2 images. Clipping (W/W*) and blend
  modes remain unhonoured; rendering is aliased (hard edges).

== v1.12.0 — 2026-06-06 — Rasterizer : text rendering (embedded TrueType glyphs)

=== Added

* **Text rendering in `PDF::Raster`** — the rasterizer now draws glyphs,
  not just vector graphics. Real pages (table of contents, body text…)
  render legibly.
  ** `Raster::Glyph` — TrueType `glyf` outline extraction : simple and
     composite glyphs, on/off-curve points, quadratic-Bézier
     flattening.
  ** `Raster::Font` — loads the embedded TrueType program (`/FontFile2`)
     of a PDF font, exposes glyph contours and advances, and decodes
     codes → GID. Covers composite Type0 fonts (CIDFontType2,
     Identity-H, 2-byte codes, `CIDToGIDMap`) and simple TrueType fonts
     (1-byte via `cmap`).
  ** `Raster::Interpreter` — full text state and operators (BT/ET, Tf,
     Td/TD/Tm/T*, TL/Tc/Tw/Tz/Ts/Tr, Tj/TJ/'/"), with the text
     rendering matrix and per-glyph advance. The content lexer now
     decodes string operands (literal escapes + hex).

=== Note

* Still not rendered : images (image XObjects), Type1/CFF (non-TrueType)
  fonts — those text runs are skipped. Clipping (W/W*) and blend modes
  remain unhonoured. Next milestone : images.

== v1.11.0 — 2026-06-06 — Native rasterizer : `pdftoppm` / `pdftocairo` (MVP, no ghostscript)

=== Added

* **`PDF::Raster`** (`src/pdf/raster/`) — a pure-Crystal PDF
  rasterizer, the engine behind poppler's `pdftoppm` / `pdftocairo`,
  with **no ghostscript / cairo dependency**. This first milestone (MVP)
  renders **vector** content :
  ** `Raster::Matrix` — PDF affine transforms (CTM, concatenation).
  ** `Raster::Canvas` — RGBA buffer with scanline polygon fill
     (non-zero and even-odd winding), thick-segment stroking, and
     PNG (`stumpy_png`) / PPM (Netpbm) output.
  ** `Raster::ContentLexer` — content-stream tokenizer (operands,
     operators, inline-image skip).
  ** `Raster::Interpreter` — executes path construction (m/l/c/v/y/re/h),
     painting (f/f*/S/s/B/B*/b/b*), graphics state (q/Q/cm/w) and
     Device colours (g/rg/k + sc/scn by component count), with Bézier
     flattening.
  ** `PDF::Raster.render_page(reader, index, dpi)` → `Canvas`.
* **`pdftoppm` and `pdftocairo` binaries** (`src/bin/`) — new shard
  targets, ALOLI CLI conventions. `pdftoppm <doc> [<prefix>]` (`-r`,
  `--png`/PPM, `-f`/`-l`, `-p`), `pdftocairo <doc> [<out>]` (`-png`,
  `-r`, `-f`/`-l`, `--singlefile`, `-p`).

=== Note

* **MVP scope.** Vector graphics only. Text (glyph rendering) and
  images (image XObjects) are consumed without output for now —
  upcoming milestones. Clipping (W/W*), patterns and blend modes are
  not yet honoured.

== v1.10.0 — 2026-06-05 — `pdfattach` : attach a file to an existing PDF (poppler-utils equivalent)

=== Added

* **`PDF::AttachedFile.attach`** — attaches a file to an already-open
  document, the library equivalent of poppler's `pdfattach`. The file
  is added both to the `/Names /EmbeddedFiles` name tree (viewer
  visibility) and to `/AF` (associated files — PDF/A-3, Factur-X,
  ZUGFeRD), reusing the existing `EmbeddedFile` / `FileSpec` builders.
  Written via incremental update, so the original bytes are preserved.
* **General incremental-update API on `PDF::Reader`** — `add_object`
  (append a new indirect object, returns its reference),
  `replace_object` (re-emit a modified existing object), `catalog` /
  `catalog_reference` (mutate the `/Root` dict). `Reader#write` now
  emits these alongside the existing page-content-stream path
  (watermarking), with no change to that behaviour.
* **`pdfattach` binary** (`src/bin/pdfattach.cr`) — new shard target,
  ALOLI CLI conventions. `pdfattach <doc.pdf> <file> -o OUT
  [-n NAME -d DESC -m MIME -r RELATIONSHIP]`. The source document is
  never modified; the result is written to a new file.

=== Note

* Known limitation : attaching to a document that already has an
  intermediate-node (`/Kids`) `/EmbeddedFiles` tree preserves only the
  root node's files in the tree (all remain listed via `/AF`).

== v1.9.0 — 2026-06-05 — `pdfimages` : list and extract images (poppler-utils equivalent)

=== Added

* **`PDF::ImageInfo`** (`src/pdf/image_info.cr`) — enumerates and
  extracts a document's images (`/XObject` subtype `/Image`, ISO
  32000-1 § 8.8), the library equivalent of poppler's `pdfimages`.
  Walks every page's `/Resources /XObject` and recurses into Form
  XObjects (depth-guarded). Reports dimensions, bits-per-component,
  normalised colour space (rgb/gray/cmyk/icc/index/sep/devn/lab/mask),
  component count, encoding filter and stream size; deduplicated by
  object number.
* **Image extraction** — `#write_to` chooses the output format from the
  filter: `/DCTDecode` images are written as `.jpg` byte-for-byte
  (passthrough), `/FlateDecode` samples are exported as Netpbm
  PPM/PGM/PBM (like poppler's default), other filters keep their raw
  bytes. Pure reading — the source document is never modified.
* **`pdfimages` binary** (`src/bin/pdfimages.cr`) — new shard target,
  ALOLI CLI conventions. `--list` (poppler format, plus `--json`),
  `--save-all -d DIR -o PREFIX`.

== v1.8.0 — 2026-06-05 — `pdfdetach` : list and extract embedded files (poppler-utils equivalent)

=== Added

* **`PDF::AttachedFile`** (`src/pdf/attachments.cr`) — enumerates and
  extracts a document's embedded files, the library equivalent of
  poppler's `pdfdetach`. Three sources are walked (ISO 32000-1) :
  ** `/Root /Names /EmbeddedFiles` name tree (§ 7.11.4),
  ** `/Root /AF` associated files (§ 14.13 — PDF/A-3, Factur-X,
     ZUGFeRD),
  ** page `/FileAttachment` annotations (§ 12.5.6.15).
+
Reports filename (`/UF` then `/F`, decoded), description, MIME type,
declared size and `/AFRelationship`; `#data` returns the decompressed
bytes. Deduplicated by the embedded stream's object number.
* **`pdfdetach` binary** (`src/bin/pdfdetach.cr`) — new shard target,
  ALOLI CLI conventions. `--list` (poppler format, plus `--json`),
  `--save N -o FILE`, `--save-all -o DIR`. Pure reading — the source
  document is never modified.

== v1.7.0 — 2026-06-05 — Metadata tools : `pdfinfo` and `pdffonts` (poppler-utils equivalents)

=== Added

* **`PDF::Info`** (`src/pdf/info.cr`) — metadata extraction over an
  existing document, the library equivalent of poppler's `pdfinfo` :
  ** `/Info` fields (title, author, subject, keywords, creator,
     producer), with PDF text-string decoding (UTF-16BE/LE BOM,
     PDFDocEncoding) so accented titles render correctly.
  ** `CreationDate` / `ModDate` parsed from `D:YYYYMMDD…` strings
     (ISO 32000-1 § 7.9.4) into `Time`.
  ** PDF version, page count, first-page size with standard-format
     naming (A4, Letter, Legal…), page rotation, encryption flag,
     Tagged PDF, XMP metadata stream, AcroForm presence, file size.
* **`PDF::FontInfo`** (`src/pdf/font_info.cr`) — font enumeration, the
  library equivalent of poppler's `pdffonts` : walks each page's
  `/Resources /Font`, deduplicates by object number, and reports name,
  program type (Type 1, TrueType, CID TrueType…), encoding, and the
  embedded / subset / unicode flags. Resolves Type0 composite fonts
  through `/DescendantFonts`.
* **`pdfinfo` and `pdffonts` binaries** (`src/bin/`) — new shard
  targets, following ALOLI CLI conventions (`help [<sub>]`,
  `-h`/`--help`, `-V`/`--version`, a short for every long flag). Output
  matches poppler's format, plus a `--json` variant consistent with
  `pdf2text`. Both are reachable through the `alolipdf` front-end
  (subcommands `info` / `fonts`).

== v1.6.0 — 2026-06-04 — NChannel mixing hints (/Solidities, /PrintingOrder, /DotGain)

=== Added

* **`NChannel` mixing hints** (ISO 32000-1 § 8.6.6.5) via three
  optional constructor arguments :
  ** `solidities : Hash(String, Float64)` → `/MixingHints /Solidities`
     (per-colorant opacity in `[0, 1]`, plus an optional `"Default"`).
  ** `printing_order : Array(String)` → `/MixingHints /PrintingOrder`
     (colorant lay-down order).
  ** `dot_gain : Hash(String, Float64)` → `/MixingHints /DotGain`,
     each value the exponent `N` of a Type-2 transfer function
     `f(t) = t^N` over `[0, 1]` (`N < 1` boosts midtones).
* `/MixingHints` is emitted only when at least one of the three is
  supplied.

=== Validation

* `solidities` values must be in `[0, 1]` and keyed by a colorant name
  or `"Default"` ; `printing_order` names must be colorants ;
  `dot_gain` exponents must be `> 0`. Per § 8.6.6.5, supplying
  `solidities` without `printing_order` raises.

=== Tests

* Specs : emission and omission of `/MixingHints`, the three
  sub-entries (including the Type-2 `/DotGain` function), and every
  validation path.
* Validated with veraPDF (`-f 2b`) : a PDF/A-2b document with an
  NChannel carrying full mixing hints is fully compliant (144/144
  rules). This closes the § 6.2.4.4 / § 8.6.6.5 colour-space work.

== v1.5.0 — 2026-06-04 — NChannel colour space (/Subtype /NChannel, /Process)

=== Added

* **`PDF::ColorSpaces::NChannel`** — a specialised `DeviceN` whose
  attributes dictionary carries `/Subtype /NChannel`, the modern form
  for spaces mixing process inks with spot colorants. Subclass of
  `DeviceN` : it reuses the array form, the tint transform and the
  `/Colorants` logic (PDF/A-2 § 6.2.4.4, v1.3.0), and always emits an
  attributes dictionary.
* Optional **`/Process`** description via the `process_components`
  constructor argument : emits `/Process << /ColorSpace [/ICCBased
  ref] /Components [names] >>`. Validated against the alternate's
  channel count and the colorant name list.
* Usable on a page with no API change : because `NChannel` is a
  `DeviceN`, `Page#color_space` / `Page#fill_color` / `Page#stroke_color`
  accept it directly (tint count = number of colorants).

=== Conformance notes

NChannel is subject to the same § 6.2.4.4 `/Colorants` requirement as
DeviceN ; the inherited logic covers it. This completes the § 6.2.4.4
coverage (DeviceN *and* NChannel).

=== Tests

* Specs : `/Subtype /NChannel`, inherited `/Colorants`, `/Process`
  dictionary, `process_components` arity / membership validation, and
  Page integration (registration, `scn`, byte output).
* Validated with veraPDF (`-f 2b`) : a PDF/A-2b document filling an
  NChannel (CMYK process + spot, with `/Process`) is fully compliant
  (144/144 rules), generated via the public API.

== v1.4.0 — 2026-06-04 — Separation / DeviceN usable on a page (cs/scn, /ColorSpace)

=== Added

* **`Page#color_space(space)`** — registers a `Separation` or `DeviceN`
  colour space into the page's `/Resources /ColorSpace` and returns its
  resource name (`"CS1"`, `"CS2"`, …). Re-registering the same instance
  returns the same name (no duplicate object).
* **`Page#fill_color(space, *tints)` / `Page#stroke_color(space,
  *tints)`** — convenience : select the special colour space and set
  the colour in one call (emits `/CSn cs` + `scn`, resp. `/CSn CS` +
  `SCN`). The tint count must match the space (1 for a Separation, N
  for a DeviceN) — raises `ArgumentError` otherwise.
* **`Page#fill_tint(*tints)` / `Page#stroke_tint(*tints)`** — low-level
  `scn` / `SCN` emitters for an already-selected colour space.
* **`Document#icc_profile_ref(icc)`** — embeds an ICC profile stream
  once and returns its reference ; a profile shared as the alternate of
  several Separation / DeviceN spaces (or as the output intent) is
  written only once.
* `build_resources` now emits the `/ColorSpace` sub-dictionary.

=== Notes

Until now `Separation` / `DeviceN` (and their PDF/A-2 § 6.2.4.4
`/Colorants`, v1.3.0) could be built but not actually placed on a page
through the public API. This release wires them end-to-end : a page can
fill/stroke with a spot or multi-ink colour.

=== Tests

* Specs : resource-name allocation and deduplication, `/ColorSpace`
  emission, `cs`/`scn` and `CS`/`SCN` content, tint-arity validation,
  document-level ICC deduplication, and end-to-end byte output.
* Validated with veraPDF (`-f 2b`) : a PDF/A-2b document filling a
  DeviceN spot space *and* a Separation spot space (sharing one ICC
  profile) is fully compliant (144/144 rules) — generated via the
  public API, no internal hooks.

== v1.3.0 — 2026-06-04 — DeviceN spot colorants (/Colorants, PDF/A-2 § 6.2.4.4)

=== Added

* **`DeviceN#to_array` now emits the attributes dictionary** (5th array
  element) with a `/Colorants` sub-dictionary, as required by ISO
  19005-2 (PDF/A-2) § 6.2.4.4 : every *spot* colorant of a DeviceN /
  NChannel space must be described there. Each spot colorant maps to a
  `Separation` array `[/Separation /<name> <alternate> <tintTransform>]`
  (reusing the `Separation` class), built from the DeviceN's own
  alternate space and per-component `c1` vector.

=== Fixed

* A DeviceN space carrying spot colorants previously produced only the
  4-element form `[/DeviceN [names] alternate tintTransform]` with no
  `/Colorants` — a latent PDF/A-2 non-conformance (§ 6.2.4.4 t1),
  analogous to the earlier sRGB v4 output-intent defect.

=== Conformance notes

A *spot* colorant is any name that is neither a standard CMYK process
ink (`Cyan`/`Magenta`/`Yellow`/`Black`) nor a reserved name
(`None`/`All`). When a DeviceN carries no spot colorant the attributes
dictionary is optional and is omitted (ISO 32000-1 § 8.6.6.5).

=== Tests

* Specs : `/Colorants` entry per spot colorant, key encoding matching
  the names array, omission for all-process / reserved-name spaces, and
  spot-only filtering when mixed with process inks.
* Validated with veraPDF (`-f 2b`) : a PDF/A-2b document using a DeviceN
  spot space passes § 6.2.4.4 (144/144 rules, fully compliant) ; the
  same document built without `/Colorants` fails exactly clause 6.2.4.4
  test 1.

== v1.2.0 — 2026-06-03 — TJ and Tc operators (positioning and spacing)

=== Added

* **`Page#text_positioned` — the `TJ` operator** (Show Text Allowing
  Individual Glyph Positioning, ISO 32000-1 § 9.4.3). The universal
  tool (simple *and* composite fonts) : `runs` mixes strings (shown
  with the current font's encoding) and numbers (position adjustments,
  in thousandths of a unit of text space, subtracted from the current
  position). `char_spacing` and `word_spacing` may be combined.
+
[source,crystal]
----
page.text_positioned(["A", -80, "V", -80, "A"], at: {72, 700})
----
* **`Page#text` accepts `char_spacing` — the `Tc` operator** (Character
  Spacing, ISO 32000-1 § 9.3.2) : spacing added after every glyph.
  Unlike `Tw`, `Tc` applies to *all* fonts (simple and composite),
  making it the tool for **justifying CJK text** (where characters are
  spread out, there being no inter-word spaces). Emitted before the
  show and reset to `0` within the same text object.

=== Conformance notes

`TJ` (§ 9.4.3) and `Tc` (§ 9.3.2) complement `Tw` (§ 9.3.3, v1.1.0) :
`Tw` for word spacing on simple fonts, `Tc`/`TJ` for spacing and
fine positioning that also work on multi-byte composite fonts.

=== Tests

* Specs : `Tc`/`0 Tc` emission (simple *and* composite TrueType via
  DejaVuSans), a `TJ` array mixing strings and adjustments (simple and
  composite), and combined `Tc` + `TJ`. Verified with qpdf ("No syntax
  or stream encoding errors").

== v1.1.0 — 2026-06-03 — Native word spacing (Tw operator)

=== Added

* **`Page#text` accepts `word_spacing`** — word spacing is now set via
  the native PDF `Tw` operator (ISO 32000-1 § 9.3.3) instead of
  word-by-word positioning in Crystal. `Tw` is emitted before the show
  and reset to `0` within the same text object (BT…ET), so it stays
  local and does not leak into subsequent text.
* **`Page#composite_font?`** — reports whether the current font is a
  composite (multi-byte, Type0/CID) font.

=== Changed

* **Justified text (`Text::Formatted::Box`)** — for a simple
  (standard-14 / Type1) font, justification now uses `Tw` (one `Tj`
  per fragment) instead of drawing each word separately : shorter,
  more idiomatic content streams, identical visual output.
+
Spec-compliant : `Tw` only applies to the single-byte code 32
(ISO 32000-1 § 9.3.3). For a composite (multi-byte) font, where that
code is not the space, rendering keeps word-by-word positioning (the

== v0.7.1 — 2026-06-02 — Tagged PDF marked content (J2, palier 2/4)

Ties the logical structure tree (0.7.0) to the actually-rendered
content — the heart of a real Tagged PDF, and what a PDF/UA
validator follows from structure down to glyphs.

=== Added

* **Marked content on `Page`** :
** `Page#marked_content(tag) { … }` wraps the block's drawing in a
   `/<tag> <</MCID n>> BDC … EMC` sequence, assigns a fresh per-page

== v0.6.3 — 2026-06-01 — CFF subsetter (charstring collapse, palier 3/4)

=== Added

* **CFF subsetter** — palier 3 of the native OTF subsetting
  trajectory. New class `PDF::Fonts::CFF::Subsetter` produces a
  reduced CFF blob from a parsed CIDFont :
+
[source,crystal]
----
subset_bytes = PDF::Fonts::CFF::Subsetter.new(cff_parser, kept_gids).subset
----
+
* Unused glyph charstrings are collapsed to a single `endchar`
  byte ; kept glyphs retain their exact original bytes. GID 0
  (`.notdef`) is always preserved.
* The Top DICT, FD Font DICTs and Private DICTs are re-emitted with
  patched offsets ; Charset and FDSelect are copied verbatim (GID
  numbering is preserved, so they stay valid without remapping).
* Local and global subroutines are copied verbatim with their
  original indices — no renumbering — so every `callsubr` /
  `callgsubr` in surviving charstrings stays valid.

* **`PDF::Fonts::CFF::IndexWriter`** — serialises a CFF INDEX from
  byte entries (the inverse of `CFF::Index`), choosing the smallest
  valid `offSize`.

* **BCD real encoding** in the subsetter's DICT writer, so Top DICT
  operands like the font version (`1.004`) round-trip correctly.

=== Validated against

* `NotoSansCJKsc-Thin.otf` (13.5 MB CFF) subsetted to a 200-glyph
  document : output **1.43 MB (10.4 % of original, ~90 % reduction)**
  in 0.01 s. Re-parsing the subset succeeds, kept glyph 100 is
  byte-identical to the source, dropped glyphs collapse to a single
  `endchar`, and all 200 kept glyphs re-analyse cleanly.
* 3 `IndexWriter` round-trip specs + 2 subsetter integration specs.

=== Deferred

* **Subr pruning.** The remaining ~10 % (mostly retained subrs) needs
  a full Type 2 stack interpreter to renumber subrs safely — a
  `callsubr` may consume a value pushed by a previously-called subr,
  so the operand preceding a call cannot always be rewritten in
  isolation. Out of scope for this palier ; the charstring collapse
  already recovers the bulk of the size. Tracked for a later 0.6.x.

== v0.6.2 — 2026-06-01 — Type 2 charstring analyser (palier 2/4)

=== Added

* **CFF Type 2 charstring analyser** — palier 2 of the native OTF
  subsetting trajectory. New class `PDF::Fonts::CFF::Type2Analyser`
  walks the bytecode of a glyph without rendering it, tracking which
  local and global subroutines are referenced — *transitively*, by
  following `callsubr` (10) and `callgsubr` (29) into their target
  subrs.
+
[source,crystal]
----
analyser = PDF::Fonts::CFF::Type2Analyser.new(cff_parser)
local_used, global_used = analyser.analyse(gid)
# => {Set(Int32), Set(Int32)} of subroutine indices reached from
# this glyph (transitively across nested callsubr/callgsubr).
----
+
The output feeds palier 0.6.3 (subsetter), which uses it to compute
the closure of subrs to keep when stripping unused glyphs.

=== Implementation notes

* **Subroutine bias** : the analyser implements the Tech Note #5176
  § 4.7 bias formula (107 / 1131 / 32768 depending on subr count).
* **CIDFont awareness** : for CIDFonts the per-glyph local subr set
  is selected via FDSelect → FDArray[fd]'s Private DICT.
* **Hint-mask peculiarity** : `hintmask` (19) and `cntrmask` (20)
  are followed by a `ceil(num_stems / 8)`-byte bitmask whose length
  depends on the cumulative stem count across the *whole glyph*,
  including any stems declared inside called subrs. The walker
  shares a `WalkState` across nested calls to track this correctly.
* **Cycle protection** : subr indices are recorded in a `Set` before
  recursion ; a second visit to the same subr is skipped, so cycles
  (illegal but real in some pathological fonts) cannot blow the stack.

=== Validated against

* 10 unit specs covering subr bias, callsubr/callgsubr, nested
  subrs, dedup, hintmask skipping, out-of-range subr indices.
* Smoke test on `NotoSansCJKsc-Thin.otf` (15 MB, 65 535 glyphs,
  19 FDs, 2 342 global subrs) : entire font analysed in **0.83 s**
  with no errors. 100 % of global subrs and ~99-100 % of per-FD
  local subrs are reached when traversing all glyphs (expected on
  a full font — subsetting will reduce these numbers in 0.6.3).

== v0.6.0 — 2026-06-01 — J1 milestone closure

This release closes milestone **J1** of the ISO PDF trajectory
(cf. `doc/RATIONALE.adoc`). The shard now generates documents that
exercise every prerequisite of PDF/A-2b / PDF/A-3 :

* Calibrated colour management (OutputIntent + ICCBased — v0.5.8)

  flags (AcroForm — v0.5.7 to v0.5.10)

* Compressed objects (Object streams — this release)

the same code base.

=== Added

* **Cross-reference streams (`/Type /XRef`).** New
  `Document#xref_format = :stream` switches from the classic
  `xref ... trailer ... %%EOF` block to a Flate-compressed
  cross-reference stream (PDF 1.5+). The stream dict carries the
  trailer entries (`/Size`, `/Root`, `/Info`, `/Encrypt`, `/ID`,

  objects).

  spot inks (Pantone, Cutter, etc.) with an `ICCBased` fallback
  and a Type-2 linear tint transform. Compatible with PDF/A-2b
  when paired with FOGRA39.

* **DeviceN colour space.** `PDF::ColorSpaces::DeviceN` — N-channel
  spot or process colour. MVP tint transform sums per-component
  contributions ; production usage should provide a
  FunctionType 4 tint for accuracy.

=== Changed

* Writer rewritten to support three operating modes : classic table
  (`xref_format = :table`), xref stream (`:stream`), and xref stream
  + object streams (`object_streams = true`).
* Documents with object streams are typically 8-20 % smaller than
  the same documents in classic mode. The exact gain depends on
  the number of compressible indirects.

== v0.3.4 — 2026-04-25

=== Fixed

* **Reading back PDFs amended via `add_content_stream`**.
  `PDF::Reader.open` crashed with `Invalid Int32: ""` (raised from
  `find_xref_offset`) when re-opening any PDF that contained a
  binary content stream — typically a stream with bytes ≥ 0x80,
  produced by `crystal-watermark`, `crystal-combine-pdf` and any
  other downstream library that appends content via the incremental
  update mechanism (PDF spec § 7.5.6).

  Root cause: `find_xref_offset` searched for `"startxref"` via
  `String#rindex`, which returns an offset in **characters** (UTF-8).
  As soon as a multi-byte UTF-8 sequence appeared in the search
  area (any byte ≥ 0x80 followed by a continuation byte), the
  character offset diverged from the byte offset, and
  `@pos = search_start + idx + 9` landed past the real `startxref`
  marker. `read_int` then read an empty string and crashed.

  Fix: scan the raw bytes directly via a new private
  `byte_rindex(haystack, needle, from)` helper. No interpretation
  of the bytes as UTF-8 — the search is purely byte-level and
  immune to the encoding of the surrounding content streams.

* New regression test in `spec/pdf/reader_spec.cr` ("réouvre un PDF
  amendé contenant des octets binaires (≥ 0x80)") that amends a PDF
  with a content stream covering the full byte range 0..255 and
  asserts `PDF::Reader.open` returns the correct page count.

== v0.3.2 — 2026-04-23

=== Fixed

* **SVG `Z` path command**: `renderer.cr` used `page.close_stroke` to
  terminate a subpath on `Z`, which emits the PDF `s` operator
  (close + stroke). That consumed the current path, so the
  subsequent call to `apply_fill_and_stroke` had nothing left to
  fill. Visually, closed SVG shapes rendered as thin outlines
  instead of filled colour regions — country flag SVGs in
  particular showed empty boxes instead of bands of colour. Switched
  to `page.close_path` (PDF `h` operator) so the path stays alive
  for the fill / stroke decision.

== v0.3.1 — 2026-04-23

=== Fixed

* **SVG `path_parser` tokenizer**: fix an infinite loop triggered by
  certain compact path-data strings. When a number ended with a `.`
  that was immediately followed by another `.` starting the next
  number (e.g. `4.4.8` or `3 0.5.7`, a pattern common in tightly
  packed flag SVGs), the inner number-parsing loop would break on
  the very same `.` it had just stopped at without advancing `i`,
  and the outer loop would spin forever at 100 % CPU. The fix
  unconditionally consumes the first character of a numeric token.
* Added `PDF::SVG::PathParser` specs covering the degenerate case
  and a reduced extract of the Brazil flag path that used to hang.
